# StonkLaunch · ChatGPT dot 开发启动包 v2.1

编制日期：2026-10-18（Asia/Shanghai）  
定位：**d00 已编制完成；把本包交给 dot，确认规约后执行 d01–d04。**

本包是开发规约、执行指令、接口与验收契约，不是已完成的应用源码。当前没有可运行的网站、真实平台账户、发币交易、收费到账或上线结果；也没有预填任何 PASS。应用、`src/lib/monetization.ts`、`skill/SKILL.md`、安装脚本和最终交付说明由 dot 在指定阶段生成。这样可以遵守“先规约，确认后编码”，也避免交付一个需要推倒重来的假交易壳。

## 直接使用

1. 将整个 ZIP 附给你的 dot。若客户端不能解压，就在 dot 可访问的项目目录解压，告诉它这个目录。
2. 阅读本页和 `docs/PRD_AND_ARCHITECTURE.md`。下列三项是本次有依据的修订：**已验证的计价资产，不宣称价格锚定；平台/创作者各 0.5%，协议费另列；毕业由协议指定执行者完成，应用验证并展示结果。**
3. 把 `DOT_START_PROMPT.txt` 全文发给 dot。该文件以“我已确认本包 d00”开头，你发送它后，dot 即可在既定范围内持续开发。
4. 已有 GitHub 仓库、部署服务或 Supabase 项目时，把目标链接一并给它；没有这些也可以先完成本地全栈工程、演示和部署准备。无需现在填写私钥。

建议使用的开工句：

> 我已确认附件启动包的 d00 规约及其中的协议修订。请读取 DOT_START_PROMPT.txt 和 AGENTS.md，按 d01–d04 连续完成 StonkLaunch 全栈应用。常规实现自行推进；需要我的账户接入或钱包签名时，先把可审阅的具体操作准备好，再集中说明。按实际证据报告费用与上线状态。

## dot 环境要点

dot 的云端电脑可以承担工作；本地 Work/Codex 任务需要已连接、在线且应用开启的个人电脑。若使用特定仓库的 Codex 云任务，需要对应云环境已准备好。子任务不自动继承所有历史，主任务必须传入规约、目标路径与验收标准。依据：[Tasks and memory](https://learn.chatgpt.com/docs/dots/tasks-and-memory)、[Computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps)。

不要假定本次 dot 一定拥有部署、数据库、钱包、浏览器插件或某一种模型。先发现实际能力；没有并行子任务就串行执行，没有外部凭据就完成不依赖它们的工程部分。既有权限继续有效；缺失权限不能靠提示词赋予。

## 最终状态应怎样读

- **本包完成**：说明与执行契约准备好。
- **开发交付完成**：可运行源码、完整页面、后端和相应环境的证据齐全。
- **主网商业就绪**：主网平台配置、真实费用归属/领取和适用路径验证通过。
- **多计价差异化成立**：至少一个非 SOL 候选资产完成对应链上路径验证。只展示待开放资产不能宣称该项完成。
- **已经盈利**：存在可复核的实际收入和成本记录。没有成交时实际收入是 0。

这些状态是交付结果的不同事实，不是新增开发轮次或验收门禁。
