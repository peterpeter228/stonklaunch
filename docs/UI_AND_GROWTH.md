# StonkLaunch：界面与增长设计规约

> 本文件是供 dot 实现的产品设计，不代表界面已实现、交易已测试或应用已上线。协议能力、费用字段及资产支持以 [PROTOCOL_EVIDENCE.md](PROTOCOL_EVIDENCE.md) 为准。

## 1. 产品目标与展示边界

首版保留发现、创建、交易、毕业、数据终端五个核心页面，以及后端索引、缓存、海报和费用管理。首先打通经验证的 SOL 真实路径；USDC、xStocks 和其他计价资产只有存在有效协议配置后才开放创建。没有配置时显示“待开放”，不得计入完整差异化验收。

“计价资产”只说明交易以什么资产报价，不表示固定价格锚定、抵押担保或赎回权。首页不使用“锚定股票”“保证收益”“任意资产均可发射”等超出能力的文案。第一屏回答三件事：可以创建什么、预计付出什么、完成后能做什么。

## 2. 暗黑视觉、布局与动效

### 2.1 设计 tokens

| Token | 值 | 用途 |
|---|---|---|
| background | `#070B14` | 全站底色 |
| surface | `#0F1726` | 卡片与侧栏 |
| elevated | `#162236` | 弹层、选中卡片 |
| border | `#24344D` | 分隔线与输入框 |
| text | `#EAF0FA` | 标题及主要数字 |
| muted | `#9CAEC7` | 说明和次级字段 |
| primary | `#5BE6CC` | 主操作、确认状态 |
| secondary | `#AD9BFF` | 选中项及辅助强调 |
| warning | `#FFD27D` | 待处理、数据过期 |
| negative | `#FF8392` | 错误及真实负值 |

主按钮使用浅青底和深色文字。霓虹渐变只用于首屏主卡边缘和重要完成反馈，不给每张卡添加发光。毛玻璃限于顶部栏及弹层，保证内容背景稳定。正文至少 14px，关键说明 16px；数字使用等宽数字排版。中文采用系统可用字体，避免字体下载阻塞页面。

间距采用 4/8/12/16/24/32px；输入框圆角 12px，主卡 18px。长地址默认缩写，复制与展开可获得完整地址。字段不能仅靠颜色区别，所有图标按钮提供名称、键盘焦点和可访问标签。

### 2.2 响应式布局

桌面最大内容宽度 1440px，采用 12 栏；交易与创建页为主内容 8 栏、操作区 4 栏。顶部栏固定展示品牌、当前网络、数据状态与钱包。宽屏允许侧栏；中等屏幕收起侧栏并缩短辅助信息。

360px 手机宽度必须可用。主导航只保留“发现 / 创建 / 终端”，交易与毕业通过项目详情进入。交易主操作固定在底部安全区域上方，详细费用可展开；不得遮挡金额、错误或钱包提示。表格在移动端变为卡片，禁止整页横向滚动。

### 2.3 动效规则

悬停和选中反馈约 120–180ms，卡片与弹层切换约 180–240ms。数字仅在真实新数据到达时变化；禁止用定时自增制造成交或收入。长任务展示实际阶段，不用虚构百分比。遵循减少动态效果设置，关闭持续闪烁、计数滚动和庆祝粒子。

## 3. 五个页面的执行要求

### 页面一：发现首页 `/`

首屏放“一次完成发行设置”主卡：名称、符号、计价资产入口、启动按钮。进入创建页时携带已有输入。资产选择器展示名称、符号、网络、可用状态；待开放资产可查看原因，不能被选为真实交易参数。

下方是新发行列表，可按最新、真实成交额、毕业进度排序。每项显示交易对、创建时间、曲线进度、成交额口径及数据时间。提供网络和资产筛选；不以虚构热度、假成交提醒或假倒计时填补空白。顶部统计为空时显示“暂无已索引发行”，不能显示样例收入。

### 页面二：创建工作流 `/launch`

沿用首页草稿，在同一主卡完成计价资产、代币信息、发行参数。高级参数折叠，默认值必须与协议能力一致。右侧同步展示图标、交易对、发行摘要及费用结构，不根据币名生成收益预测。

提交前显示当前网络、钱包、实际协议配置、平台费、创作者费、协议费、估计网络成本和预计动作。使用“检查并签名创建”，进入钱包前允许修改。减少应用内步骤，但不保证钱包只弹一次，也不隐藏必要授权。

成功依据真实交易确认，显示 mint、曲线地址、交易链接及“查看交易页 / 生成海报”。拒签不清空草稿；确认超时保留签名并继续查询，不能直接邀请用户重复创建。恢复草稿只保存公开表单内容，不保存密钥。

### 页面三：交易页 `/token/[mint]`

左侧展示实际行情、曲线进度与项目资料；右侧提供买入/卖出切换、金额、余额、滑点和报价。没有足够历史时显示真实事件列表，不绘制虚构 K 线。非美元计价先显示原币种，美元估值必须附价格来源与时间。

签名前至少展示支付资产与金额、预计获得、最低收到、费用明细及网络费用。总费用与各方份额按协议实际计算，不把平台费当作全部成本。切换输入、方向、网络或池状态后使旧报价失效。

页面明确当前走曲线还是毕业后 CPMM。状态变化时重新读取并报价，不沿用旧交易。成交反馈显示真实数量、签名和确认状态；无法验证的交易标为待确认，不播放成功动画。

### 页面四：毕业详情 `/token/[mint]/graduation`

以实际进度、毕业条件和检查时间为主。使用“曲线交易中 → 达到条件 → 等待或执行迁移 → 已迁移”的状态说明，异常单独显示原因与可用动作。达到阈值不等于迁移成功。

只有链上证据充分时才展示 CPMM 池地址和毕业成功。流动性区域列出可证明的 LP 处理方式、比例、账户与交易；未知部分直接标注“尚未验证”。不能从“存在 CPMM 池”推导“全部永久锁定”。毕业后的交易入口必须指向实际可用路由。

### 页面五：数据终端 `/terminal`

保留“全平台 / 我的发行 / 费用管理”三个 tab。全平台展示新币、毕业数、毕业率和费用；毕业率同时给出分子、分母及观察时间，避免混合不同时段发行批次。列表支持筛选、搜索和空态。

我的发行展示当前钱包创建的项目、曲线状态和快捷操作。费用管理区分创作者与平台权限，分别列出已产生、可领取、已领取及领取记录。钱包连接本身不代表管理员身份。

领取前预览资产、金额、目标账户及实际链上动作；确认后重新读取余额。不同资产分别统计，不直接相加。只读缓存、样例数据和未经验证的余额不能生成可签名领取交易。

创作者标准 vault 可能跨平台聚合：将“StonkLaunch 已归因费用”与“该钱包当前可领取总额”分别展示。整笔 claim 不自动归为本平台贡献，也不计成平台营业收入；无法分配来源时明确保留未归因部分。

## 4. 两个真实的心理钩子

**降低操作摩擦。** 首页输入无缝带入、可恢复草稿、合理预设、清晰拒签恢复，共同减少重复劳动。衡量开始创建、到达费用预览、请求签名、链上确认的转化与耗时；分别记录余额不足、拒签、协议不支持和服务错误。不得通过跳过费用说明提高所谓转化率。

**可验证的诞生海报。** 真实创建确认后生成海报，包含名称、符号、计价资产、网络、mint 或曲线地址，以及指向真实项目页的二维码。提供下载和打开 X 编辑器两个按钮，由用户自行发布。海报不虚构盈利、不暗示发行方背书。演示海报持续带 DEMO 水印。

可记录下载、分享入口点击、分享链接访问及后续真实创建或交易。打开编辑器不等于已发布，点击分享不等于带来新用户。

## 5. 空态、异常与模式矩阵

| 状态 | 界面行为 |
|---|---|
| 首次使用、无数据 | 解释数据来源，提供创建或刷新入口，不补入伪造业绩 |
| 演示模式 | 全局持续显示 DEMO；使用“体验流程”；不发送真实交易 |
| Devnet | 显示网络与测试资产；不得计入主网收入 |
| 真实网络 | 只有真实配置、资产、池和报价可进入签名 |
| 钱包未连接/网络不符 | 保留浏览；操作处提示连接或切换，不自动重发请求 |
| 用户拒签 | 中性提示“你取消了签名”，保留输入，可重新检查 |
| 报价过期/缓存陈旧 | 标注更新时间；交易前必须刷新，不用旧值签名 |
| 已提交、确认未明 | 展示签名与查询进度，避免重复发送 |
| RPC/索引失败 | 保留最近已知数据并标陈旧；不可核实的资金动作暂停 |
| 交易明确失败 | 展示可操作原因，不变更余额为成功结果 |

演示和真实模式不得共享交易构建输入。样例 mint、pool、金额必须在边界被拒绝；不能用消息签名冒充发币、交易或领取成功。待开放资产即使有漂亮卡片，也不能进入真实签名。

## 6. 首次获客与收入验证

以下是待验证的产品假设与内部目标，不是已获得的用户或行业基准：首批邀请 5 名拥有自身受众的创作者，确认他们是否理解并接受完整费用；至少 3 人独立完成创建可用性验证，至少 2 人使用海报或分享链接。邀请、发布或真实交易由具备相应授权的操作者执行。

访谈重点是“为什么不用已有发射台”和“是否真的需要非 SOL 计价”。SOL 闭环只能证明工程能力；其他资产未开放前，不能声称自选计价优势已经验证。没有明确需求时，先验证资产能力和创作者需要，不继续扩充无关功能。

收益看板必须区分预计费用、已确认产生、当前可领取和实际领取到账；创作者份额不属于平台收入。净收益还需扣除平台承担的 RPC、数据库、存储、数据服务及链上成本。市值、储备、成交额与 LP 未实现价值不能替代收入。

示例测算必须带条件：若实际合资格成交额为 10,000 USDC，实际平台抽成为 0.5%，对应毛费用约 50 USDC；没有成交时实际收入为 0。按交易签名与事件索引去重，失败交易、演示交易和开发人员自测不得计入商业验证。

交付时分别报告：五页设计的实现证据、真实资金路径的验收环境、资产扩展验证结果、独立外部使用和可领取收入。完整开发交付与主网上线是不同状态；没有数据的指标保留为“尚无证据”，不预填增长率或盈利承诺。
