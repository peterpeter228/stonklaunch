# d04 · 商业验收与交付契约

保留用户的五门禁，**不增轮次、不增第六门禁**。每项记录 `PASS / FAIL / BLOCKED / NOT_RUN`、验证环境、证据位置和剩余影响。当前启动包所有应用门禁均为 `NOT_RUN`；文档完成不使任何应用门禁自动通过。

## 1. 五门禁

| 门禁 | 必须证明的事实 | 不算通过的情况 |
|---|---|---|
| **GATE-1 RED_ZONE** | 无自建本金托管合约；真实交易里的 program、mint、pool/vault/接收账户符合标准协议路径；后端不保存用户资金密钥 | 仅全文搜不到 Rust；交易却含不明转账/调用，或统一归集本金进平台钱包 |
| **GATE-2 FEE_HARDCODED** | 代码默认费率存在且集中；.env 期望配置能生成标准 create/update；链上实际平台、费率与领取钱包回读一致；自家 pool 绑定该平台；至少一笔真实已确认交易支持费用归属；标准 claim 和到账证据成立 | UI 显示 0.5%、本地费用函数、模拟交易、外部池/默认平台、只改 .env、签了登录消息、只有未确认 signature |
| **GATE-3 ANTI_BORING_UI** | 五个页面可交互；暗黑主题、清楚主次、桌面/手机可用；关键操作有即时反馈、错误恢复、空态；浏览器实际走通业务旅程 | 只有设计图、白底长表单、按钮无行为、预览路由代替真实页面，或构建成功但没有看过界面 |
| **GATE-4 PSYCHOLOGY_EMBEDDED** | 首页发起并保留上下文/默认值/草稿恢复；创建确认后生成真实身份海报，并能打开分享编辑器；有完整体验证据 | 只有图标/宣传文案、伪造成功彩带、假倒计时/虚假盈利、demo 海报没水印 |
| **GATE-5 BOUNTY_READY** | `skill/SKILL.md`、API reference、`.env.example`、实际安装脚本、完整源码和两分钟分镜齐备；Skill 能按实际接口说明使用 | 只有一个空 SKILL.md、虚构工具/部署 URL、未验证即称某悬赏可投/已提交/可获奖 |

GATE-2 的 `.env` 换收款地址要求解释为 **env → 标准更新交易 → 管理钱包签名 → 链上回读生效**。这是协议事实决定的必要链路，不允许用前端变量替代。

## 2. 证据要附范围

一套证据可同时支持多项门禁，不为门禁重复建立五套测试。至少记录：

- 提交 SHA/代码位置、SDK 精确版本、cluster、时间和 RPC slot。
- 实际 PlatformConfig ID、GlobalConfig ID、平台领取公钥、可公开的 raw fee 参数。
- 一次创建、买入、卖出、费用累计/claim 的签名与结果；主网操作只在用户授权和钱包确认后执行。
- `status===2`、实际 CPMM 池、LP 处理/权利的可查证记录。用现成已毕业池验证读取时标注其来源，不声称是本次新建池完成毕业。
- 浏览器实际入口、操作结果和关键错误恢复；内部截图可用于视觉检查，若交付视频/截图应确认没有秘密或钱包敏感信息。
- 命令与返回结果的简要摘录，失败或未执行如实列出。

Devnet 五项 PASS 只证明该网络的开发验证；不能改标题为主网商业通过。演示 UI 可以单独支持 GATE-3/4，不能支持真实费用门禁。商业就绪至少要求所声明的主网路径实际证明相应收费/领取与配置。

资产能力表是五门禁报告的适用范围，不是附加门禁：

| 资产 | 创建 | 买卖 | CPMM 迁移路径 | 费用领取 | 结论 |
|---|---|---|---|---|---|
| SOL | 由 dot 填证据 | 同左 | 同左 | 同左 | 未验前不填 PASS |
| USDC | 未验保持待验证 | 分开判断 | 分开判断 | 分开判断 | 候选入口不算支持 |
| 各 xStock | 逐 mint 验证 | 逐 mint 验证 | 逐 mint 验证 | 逐 mint 验证 | 还需适用接入条件 |

如果多计价未验证而 SOL 路径通过，准确报告“SOL 范围的工程/商业验证通过，多计价目标仍有阻塞”。不能把原始全部需求写成 100% 完成。

## 3. 最小验证预算

单元测试最多两个文件：

1. `monetization.test.ts`：50 bps 与 5000 rate units、非法 env、实际平台/钱包不匹配、总费/舍入、分币种不混账。测试针对金钱错误和配置绑定，不镜像每个实现函数。
2. `lifecycle.test.ts`：迁移 0→1 不毕业；2 仍需 CPMM 证据；签名超时不重复创建；重复事件不重复入账。

一次集中的浏览器验收包括：首页 → 创建草稿 → 上传/参数校验 → 费用确认 → 钱包拒签恢复 → 有条件时真实确认 → 交易页买卖 → 海报 → 终端 → 毕业页。再检查手机宽度没有横向溢出和被遮挡的 CTA。真实钱包环境缺失时，记录模拟覆盖范围，不谎报签名成功。

类型检查、生产构建、关键 Action GET/POST/OPTIONS 与模式隔离也应实际验证，但不为了数量新增测试文件。不运行无关全链压力测试，不为低风险 CSS 改动追加测试。

## 5. `DELIVERY_README_ZH.md` 必须由 dot 实测后生成

最终说明按以下顺序写：

1. **可运行结果**：源码位置/仓库分支和 SHA、实际预览 URL、运行模式；已发布才给正式 URL。
2. **具体启动方式**：实际 Node/pnpm 版本，干净安装、环境填写、SQL migration、`dev/build/start/indexer`；不能把未执行命令写成已成功。
3. **收款配置**：平台管理员/领取公钥/平台 PDA、目标与实际费率、create/update/claim 操作、是否已链上生效、已有池行为影响。
4. **五门禁表**：状态、网络、证据、阻塞。每项只写真正证明的范围。
5. **资产和功能范围**：每种 quote 的创建/买卖/迁移/claim 能力；Actions 的规范验证与实际客户端展开分开；任何 Mock 的位置。
6. **真实链上结果**：创建、买卖、费用、毕业、LP 权利对应证据与限制；没有签名/交易时明确没有。
7. **演示材料**：上面分镜，实际录制的文件或链接（若已录）。
8. **商业口径**：实际原币种费用、已领取金额和成本；没有成交则实际收入 0，不用演示统计填补。
9. **剩余需要用户的具体动作**：已准备的管理员配置/签名、部署接入等，一次列明目的和费用上限；沿用已有授权，不重复问已决定事项。

不要生成“恭喜，全部完成”模板再填空，也不要在最后让用户自行调试未解释的脚本。阻塞时先交付完整可审阅工程和精确下一步；恢复后在同一 d04 补完证据。
